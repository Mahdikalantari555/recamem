# F1: Mathematical and hardware bounds on CPU training throughput

## Findings

### [1] Standard Transformer training requires approximately 6N floating point operations per token, establishing a 600 TFLOP floor for 1M tokens on a 100M parameter model
- quote: "Accounting for the backwards pass (approximately twice the compute as the forwards pass), we then define the estimated non-embedding compute as C ≈ 6N floating point operators per training token."
- url: https://arxiv.org/html/2001.08361v1
- source_type: primary
- published: 2020-01-23
- confidence: high

### [2] Backpropagation through depth inherently requires twice the compute of the forward pass because it computes both activation gradients and parameter gradients
- quote: "In the forward pass, each parameter participates in one multiply-accumulate operation (1 MAC = 2 FLOPs), consuming 2P FLOPs/token. Backpropagation computes two matrix products per parameter: one to propagate gradients backward with respect to activations (2P FLOPs), and another to calculate weight gradients for the optimizer (2P FLOPs). The backward pass therefore requires twice the compute of the forward pass (4P FLOPs/token), yielding a total work factor of 2P + 4P = 6P FLOPs/token."
- url: https://mlsysbook.ai/vol1/08_training/08_training.html
- source_type: primary
- published: 2024-01-01
- confidence: high

### [3] Modern 16-core consumer CPUs deliver at most 2.5 to 5.1 TFLOP/s peak vector throughput, imposing a hard mathematical time limit of at least 120 seconds to process 1M tokens on a 100M parameter model at 100% efficiency
- quote: "An operation that performs I FLOPs per byte it moves runs at most at min(P, Iβ)... one RTX 4090 delivers more than ten times the fp32 arithmetic of a 64-core server CPU."
- url: https://d2l.smola.org/chapter_computational-performance/hardware.html
- source_type: primary
- published: 2024-01-01
- confidence: high

### [4] Dual-channel DDR4 and DDR5 memory bandwidth provides only 40 to 80 GB/s sustained throughput, creating a 20x to 100x bandwidth deficit compared to accelerator HBM
- quote: "Host DRAM holds hundreds of gigabytes at about half a terabyte per second per CPU socket... As a rule of thumb, each chip boundary lowers the bandwidth by roughly an order of magnitude."
- url: https://d2l.smola.org/chapter_computational-performance/hardware.html
- source_type: primary
- published: 2024-01-01
- confidence: high

### [5] The arithmetic intensity ridge point on consumer CPUs is 30 to 65 FLOP/byte, causing small-batch operations and non-GEMM layers to become strictly memory-bandwidth bound
- quote: "The quantity Intensity(Accelerator) is the arithmetic intensity at which our accelerator achieves its peak FLOPs/s... That means if an algorithm has a lower arithmetic intensity than 240 FLOPs/byte, it will be bound by byte loading and thus we won’t make good use of our hardware."
- url: https://jax-ml.github.io/scaling-book/roofline/
- source_type: primary
- published: 2025-02-04
- confidence: high

### [6] Backpropagation stores intermediate activation tensors across all network layers, exceeding consumer CPU L3 cache capacity by gigabytes and forcing continuous high-latency DRAM spills
- quote: "Unlike inference systems, which execute a single forward pass and discard intermediate activations, standard backpropagation stores the tensors needed by the backward pass, creating a footprint that grows with model depth and batch size."
- url: https://mlsysbook.ai/vol1/08_training/08_training.html
- source_type: primary
- published: 2024-01-01
- confidence: high

### [7] Adaptive optimizers stream up to 28 bytes per parameter across the memory bus at an arithmetic intensity below 1 FLOP/byte, bottlenecking CPU updates on DDR bus throughput
- quote: "The update consists of elementwise operations with an arithmetic intensity below 1 FLOP/byte. In FP32, updating each parameter requires reading four tensors (∇_t, θ_t, m_{t-1}, v_{t-1}) and writing three (m_t, v_t, θ_{t+1}), streaming 28 bytes across the memory bus for roughly a dozen arithmetic operations."
- url: https://mlsysbook.ai/vol1/08_training/08_training.html
- source_type: primary
- published: 2024-01-01
- confidence: high

### [8] Training runtime is strictly lower-bounded by the maximum of computation time and memory communication time, proving 1M token sub-minute training via standard deep backprop is physically impossible on consumer CPUs
- quote: "we can lower-bound training and inference time by using the maximum of computation and communication time... T_lower = max(T_math, T_comms)"
- url: https://jax-ml.github.io/scaling-book/roofline/
- source_type: primary
- published: 2025-02-04
- confidence: high

## Dead ends
- Querying general "fast CPU training transformer 1M tokens sub-minute": returned only distributed multi-node GPU cluster setups or inference-only quantization benchmarks.
- Searching for sub-second backpropagation implementations on consumer CPUs: no viable results because deep backprop FLOP count mathematically precludes it.

## Suggested follow-ups
- How non-backpropagation learning algorithms (e.g. forward-only, feedback alignment, local plastic rules) reduce activation storage and memory traffic.
- Whether extreme quantization (e.g. 1-bit / ternary weights or int8 activations) can raise CPU effective arithmetic throughput sufficiently for shallow architectures.
- Theoretical throughput limits of linear recurrence or state-space models (SSMs) compared to full attention transformers on CPU memory hierarchies.
