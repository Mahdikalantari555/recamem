# F3 — Memory-Augmented Language Models & Plastic Memory for Continual Learning

Research compiled for RecaMem. Focus: memory-augmented / plastic-memory approaches for continual learning, external & episodic memory, RAG, and how they compare to weight updates — with emphasis on small models and CPU. Evidence 2024–2026. Complements F1 (online learning / TTT) and F2 (CPU inference).

## 1. Taxonomy: where experience lives

- **Citation:** Hu, Y. et al. "From Human Memory to AI Memory: A Survey on Memory Mechanisms in the Era of LLMs." arXiv:2504.15965, 2025 (Huawei Noah's Ark Lab).
- **Quote:** "a comprehensive three-dimensional, eight-quadrant (3D-8Q) taxonomy that organizes AI memory based on object (personal vs. system), form (parametric vs. non-parametric), and time (short-term vs. long-term)."
- **Dim-1 Form:** parametric (knowledge in weights) vs non-parametric (external stores: vector DB, KG, episodic buffers).
- **Dim-2 Time:** short-term (session) vs long-term (cross-session).
- **Dim-3 Object:** personal (user-specific) vs system (reasoning/tool patterns).
- **Implication for RecaMem:** RecaMem is a *hybrid* — plastic adapter (parametric, fast tier) + episodic SQLite (non-parametric, long-term) + dense anchor (parametric, frozen). This is the "additional-parametric memory module" quadrant (Wang et al., 2024c) plus contextual episodic.

- **Citation:** Du, Y. et al. "Rethinking Memory in AI: Taxonomy, Operations, Topics, and Future Directions." arXiv:2505.00675, 2025.
- **Quote:** "six fundamental memory operations: Consolidation, Updating, Indexing, Forgetting, Retrieval, and Compression" mapped to "parametric and contextual forms."
- **Use:** RecaMem already implements all six (FAST write = updating; sleep replay = consolidation; utility retirement = forgetting; two-channel recall = retrieval; schema-versioned plastic state = indexing; consolidate-then-forget = compression). Good alignment signal.

## 2. RecaMem-style plastic memory (this project)

- **Approach:** Frozen foundation model supplies language; RecaMem supplies adaptive long-term memory via a *plastic adapter* (associative memory) updated at inference without backprop through the backbone, plus an episodic SQLite store with active/retired tiers and provenance.
- **FAST tier:** no-grad associative writes, `effective_lr = base_lr / sqrt(1 + step_count/20)`; inverse-sqrt schedule; applied rate recorded per write; `h_trace` absorbs gain. See `recamem/plasticity.py::fast_write`.
- **SLOW tier:** bounded meta-parameters (`SlowTier`, `nn.Linear(dim,dim)` identity init) trained by replay on MSE + Memory-Aware Synapses (MAS) penalty; `gated_update` commits only when no probed domain drops > tolerance (default 0.05) — else restores snapshot. See `recamem/plasticity.py::SlowTier`.
- **Retrieval:** two-channel recall (episodic verbatim facts + plastic prior) fused by a small logistic scorer over 6 features (`episodic_fused, dense_similarity, plastic_prior, lexical_rank, recency, access_count`); scorer disabled below MIN_TRAIN_ROWS/MIN_HELDOUT_ROWS, plastic prior used alone with reason reported. See `recamem/retrieval.py`.
- **Forgetting:** utility + capacity retirement, consolidate-then-forget (no hard delete). `recamem/forgetting.py`.
- **Consolidation:** sleep replay + MAS. `recamem/consolidation.py`.
- **Schema:** plastic state schema-versioned (v2); older states upgraded, newer refused by name.
- **CPU feasibility:** Entirely CPU; PyTorch + numpy + safetensors; no GPU required; anchor ONNX INT8 MiniLM (<25 MB) optional; GGUF backend optional; mock explicit opt-in only.
- **Confidence:** High (this repo's own tested implementation; offline gate + 9259-node codebase).

## 3. External / associative memory for small LMs (non-weight updates)

### 3a. Sillage — fixed-size Hebbian memory (CPU, no gradients)
- **Citation:** "Sillage: Surprise-Gated Amplitude Memory for Frozen Language Models." Zenodo DOI 10.5281/zenodo.22079015, 2026-08-24. Author: riscoss63. PyPI `sillage`.
- **Quote:** "A frozen LM reads your documents, remembers them, and predicts better next time — no gradients, no fine-tuning, no growing datastore of hidden states."
- **Mechanism:** One Hebbian matrix (4.2 MB) written as model reads; keys = sliding n-gram bindings of random token hypervectors (near-orthogonal unless exact repetition); values = amplitudes (square roots of accumulated mass); writes gated by token surprise `-ln p_LM` (free at inference). Plus semantic tier (SimHash, 12.6 MB), cold store consolidated by surprise mass, and rank-16 delta-rule adapter on readout (3.2 MB).
- **Numbers:** GPT-2 124M perplexity 31.2 → 19.2 (−38%) on 36k-token novel technical text; beats unbounded kNN-LM (55 MB) at 13x less memory; +fast weights → 16.8 (−46%), 7.4 MB total. Qwen3-0.6B statistically matches unbounded kNN-LM at 1/16 memory. Recall of recurring technical terms 11.3% → 23.7%.
- **Capacity sizing law:** saturates at 0.5 writes/param; leaky decay recovers 2.3x gain; 4x larger matrix recovers 3.4x. Unbounded kNN-LM dominates on long low-repetition narrative (honest regime boundary).
- **CPU:** pure numpy, ~2 min/10k tokens (GPT-2), ~8 min (Qwen3-0.6B). Fixed 7.4–26.5 MB. No GPU.
- **Relevance to RecaMem:** Directly comparable design point — surprise-gated Hebbian writes, amplitude encoding, fixed budget, no gradients. RecaMem's plastic adapter is the analogue; Sillage's amplitude/surprise gating and capacity law are transferable lessons.
- **Confidence:** High (peer-preprint with 5 seeds, bootstrap CIs, ablations).

### 3b. Larimar — external associative memory for LLMs (CPU offload)
- **Citation:** Das, S. et al. "Larimar: Large Language Models with Episodic Memory Control." arXiv:2407.01437 (needle-in-haystack evaluation), 2024. IBM.
- **Quote:** "a relatively smaller size Larimar is able to maintain strong performance without any task-specific training... all memory operations can be performed on one or more CPUs."
- **Mechanism:** Encoder-decoder LLM (1.3B) + linear associative memory (Kanerva-Machine-like, least-squares updates). Context written as encoded sentences into memory slots keyed by prefix; readout conditions decoder. Memory size grows with context but lives on CPU.
- **Numbers:** Recall at 100K–1M tokens with training context only 384 tokens; 1.3B model; no task-specific training.
- **CPU:** Memory ops on CPU; encoding/decoding on GPU (or CPU). Off-GPU storage.
- **Relevance:** Shows external associative memory can extend a small (1.3B) model's effective context by ~1000x with CPU-resident memory.
- **Confidence:** Medium-High.

### 3c. EM-LLM — human-inspired episodic memory (no fine-tuning)
- **Citation:** Fountas, Z. et al. "EM-LLM: Human-inspired Episodic Memory for Infinite Context LLMs." ICLR 2025. github.com/em-llm.
- **Quote:** "organises sequences of tokens into coherent episodic events using a combination of Bayesian surprise and graph-theoretic boundary refinement in an online fashion... outperforms RAG... surpasses full-context models... retrieval across 10M tokens."
- **Mechanism:** No fine-tuning; online event segmentation by Bayesian surprise + boundary refinement; two-stage retrieval (similarity + temporal contiguity). Works on base LLMs.
- **Relevance:** Event-based episodic memory + surprise gating aligns with RecaMem's episodic store + FAST write surprise; provides a segmentation principle RecaMem could adopt for long streams.
- **Confidence:** High (ICLR 2025).

### 3d. Hippo-llm-memory — hippocampal episodic modules for small LMs
- **Citation:** github.com/ArneDeutsch/hippo-llm-memory (experimental, 2025).
- **Mechanism:** HEI-NW (sparse episodic index, neuromodulated writes, partial-cue recall, replay consolidation) + SGC-RSS (schema-guided semantic KG) + SMPD (spatial map). Cross-attention adapter reads episodic traces; background consolidation distills episodes into base weights.
- **Relevance:** Conceptual blueprint for RecaMem's two-tier (episodic → semantic consolidation) but unproven/experimental; useful as design reference only.
- **Confidence:** Low (unfinished, AI-generated repo).

### 3e. CellularFlow — associative DNA memory banks + episodic slots
- **Citation:** github.com/celcilin/cellularflow (2025).
- **Quote:** "83.9% retention across sequential domains... zero-backprop streaming learning during inference... replaces dense FFN with Multi-Head Associative DNA Memory Banks + Episodic Memory Slot Buffer."
- **Mechanism:** Three modes: (1) live learning via EMA writes with spherical anisotropy regularization (no backprop), (2) selective fine-tuning of memory banks only, (3) episodic fact injection with temporal decay + consolidation into banks.
- **Relevance:** Closest architectural cousin to RecaMem's FAST (no-grad writes) + SLOW (replay) + episodic store; EMA-with-regularization and temporal decay are transferable.
- **Confidence:** Medium (community project, self-reported numbers).

### 3f. RecMem — recurrence-based consolidation (LLM agent memory)
- **Citation:** Dai, C. et al. "RecMem: Recurrence-based Memory Consolidation for Efficient and Effective Long-Running LLM Agents." arXiv:2605.16045, 2026. github.com/CaiusDai/RecMem.
- **Quote:** "stores incoming interactions in a subconscious memory layer... LLMs are only invoked to extract episodic and semantic memory when sustained recurrence are observed."
- **Mechanism:** Three-tier: subconscious (embedding-indexed raw interactions, no LLM), episodic (LLM-abstraction on recurrence trigger), semantic (atomic facts). Recurrence threshold gates consolidation.
- **Relevance:** Directly informs RecaMem's consolidation gating — RecaMem already has utility-based retirement; adding a recurrence threshold (consolidate only repeated topics) would reduce cost. Name collision note: "RecMem" ≠ "RecaMem".
- **Confidence:** Medium-High (preprint).

## 4. RAG and non-parametric continual learning

### 4a. HippoRAG 2 — non-parametric continual learning via KG + PPR
- **Citation:** Gutiérrez, B. J. et al. "From RAG to Memory: Non-Parametric Continual Learning for Large Language Models." ICML 2025 (PMLR v267).
- **Quote:** "HippoRAG 2... outperforms standard RAG comprehensively on factual, sense-making, and associative memory tasks... 7% improvement in associative memory over the state-of-the-art embedding model."
- **Mechanism:** Knowledge graph + Personalized PageRank; deeper passage integration + online LLM use; addresses RAG's drop on basic factual memory when adding structure.
- **Relevance:** RecaMem's episodic store is flat; a KG/PPR layer (like SGC-RSS) would improve associative recall. Trade-off: HippoRAG 2 keeps factual performance where structured-RAG usually regresses.
- **Confidence:** High.

### 4b. Memento — memory-based online RL without weight updates
- **Citation:** "Memento: Fine-tuning LLM Agents without Fine-tuning LLMs." arXiv:2508.16153, 2025.
- **Quote:** "low-cost continual adaptation via memory-based online reinforcement learning... without gradient updates."
- **Mechanism:** Memory-augmented MDP; episodic case bank (success/failure trajectories); neural case-selection policy updated via memory rewriting; improvement via efficient memory reading.
- **Numbers:** GAIA validation 87.88% Pass@3, test 79.40%; case-based memory adds 4.7–9.6 absolute points on OOD tasks.
- **Relevance:** Case-based episodic memory + policy-over-memory is the agent-level analogue of RecaMem's fusion scorer; demonstrates memory-only adaptation can beat training-based methods.
- **Confidence:** Medium-High.

### 4c. Memory-R+ — episodic memory for tiny LLM RL (kNN memory)
- **Citation:** "Reasoning Under 1 Billion: Memory-Augmented Reinforcement Learning for Large Language Models." arXiv:2504.02273, 2025.
- **Quote:** "leverages episodic memory to address this challenge... intrinsic motivation... kNN-based episodic memory... successful reasoning traces and failed attempts."
- **Mechanism:** Two episodic memory modules (successes/failures) with kNN intrinsic rewards for tiny LLMs (≤1B) in CoT reasoning.
- **Relevance:** Memory-augmented RL helps tiny models explore; RecaMem could add a success/failure episodic split for agent tasks.
- **Confidence:** Medium-High.

### 4d. Dynamic Cheatsheet / ReasoningBank — self-curated memory for SLMs
- **Citation:** Suzgun, M. et al. "Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory." arXiv:2504.07952, 2025 (Stanford/Together AI). Community replication: Lanerra/reasoning-bank-slm.
- **Quote:** "endows a black-box LM with a persistent, evolving memory... without modifying their underlying parameters."
- **Numbers:** Claude 3.5 Sonnet accuracy more than doubled on AIME; Qwen3-1.7B 40.0% → 48.0% (+8.0 abs, +20% relative) with memory.
- **Relevance:** Most CPU-feasible non-parametric path; self-curated snippets. RecaMem already stores propositions; a self-curated "cheatsheet" layer would complement episodic facts.
- **Confidence:** High (paper) / Medium (SLM replication).

### 4e. Hierarchical parametric memory — small anchor + fetched memory bank
- **Citation:** Pouransari, H. et al. "Pretraining with hierarchical memories: separating long-tail and common knowledge." arXiv:2510.02375, 2025 (Apple).
- **Quote:** "a 160M-parameters model augmented with an 18M-parameters memory fetched from a 4.6B memory bank obtains comparable performance to a regular model with more than 2x the parameters."
- **Mechanism:** Small anchor LM (common knowledge/reasoning) + fetched parametric memory block (long-tail knowledge) added at inference; memory stored in slower/larger storage, only needed block attached.
- **Relevance:** Directly addresses edge/small models; RecaMem's byte-RTU (frozen) + plastic adapter is structurally similar (frozen anchor + small adaptive memory). Could adopt hierarchical fetch (only relevant memory block loaded).
- **Confidence:** Medium (preprint, 0 citations at capture).

## 5. Latent-space (parametric) memory — large models, CPU-offloaded LTM

### 5a. MemoryLLM / M+
- **Citation:** Wang, Y. et al. "MemoryLLM: Towards Self-Updatable Large Language Models." ICML 2024. "M+: Extending MemoryLLM with Scalable Long-Term Memory." ICML 2025 (PMLR v267).
- **Quote (M+):** "compresses past information into hidden states across all layers, forming a memory pool of 1B parameters... extends knowledge retention from under 20k to over 160k tokens... long-term memory stored on the CPU."
- **Mechanism:** Memory tokens injected into every transformer layer (1B param memory pool on 7–8B backbone); update/generate process; M+ adds long-term memory + co-trained retriever; LTM lives on CPU.
- **Scale:** 7–8B backbone + 1–1.34B memory pool; 4 weeks training on fineweb-edu. Not small/CPU-trainable.
- **Relevance:** Demonstrates latent-space memory can be CPU-offloaded for long-term retention; the *concept* (memory tokens as compressed past) is the large-model analogue of RecaMem's plastic state. Training cost is prohibitive for RecaMem's target.
- **Confidence:** High.

## 6. Sparse memory finetuning / memory layers (weight updates, but sparse)

### 6a. Sparse memory finetuning (Meta/Berkeley)
- **Citation:** Lin, J. et al. "Continual Learning via Sparse Memory Finetuning." arXiv:2510.15103, 2025 (Meta + Berkeley).
- **Quote:** "while NaturalQuestions F1 drops by 89% after full finetuning on new facts and 71% with LoRA, sparse memory finetuning yields only an 11% drop with the same level of new knowledge acquisition."
- **Mechanism:** Memory layers (Berges et al. 2024) access ~10k params out of 1–10M memory pool per forward pass; update only top-t memory slots ranked by TF-IDF (more frequently accessed on new batch vs pretraining corpus). Sparsity minimizes interference.
- **Scale:** LLMs; 1000 gradient steps. Requires memory-layer architecture (not a generic transformer).
- **Relevance:** Strong evidence that *sparse* parametric updates beat dense LoRA/full-FT for continual learning. RecaMem's plastic adapter is already sparse-ish (associative, bounded); explicit sparsity ranking could further reduce interference. But requires memory-layer backbone.
- **Confidence:** High.

### 6b. Memory bank compression (MBC)
- **Citation:** "Memory Bank Compression for Continual Adaptation of Large Language Models." arXiv:2601.00756, 2026. github.com/Thomkat/MBC.
- **Quote:** "reduces the memory bank size to 0.3%... while maintaining high retention accuracy during online adaptation learning."
- **Mechanism:** Codebook optimization to compress memory bank; online resetting to prevent codebook collapse; KV-LoRA in attention layers for efficient use of compressed memory.
- **Relevance:** If RecaMem ever stores a growing memory bank (e.g., episodic embeddings), MBC-style compression keeps it bounded. RecaMem's capacity retirement already bounds the episodic store; compression would let it hold more per byte.
- **Confidence:** Medium-High.

## 7. Fast-weight / test-time memory layers (parametric, online updates)

### 7a. Fast-weight Product Key Memory (FwPKM)
- **Citation:** "Fast-weight Product Key Memory." arXiv:2601.00671, 2026.
- **Quote:** "FwPKM stores key-value associations from the input sequence by minimizing a local reconstruction objective over chunks, in the spirit of test-time training... standard slow weights serve as Semantic Memory... FwPKM serves as Episodic Memory."
- **Mechanism:** Sparse PKM (large memory pool, small activation) updated by chunk-level gradient descent at inference; fast weights = episodic, slow weights = semantic.
- **Caveat (Finding 7):** "FwPKM adapts quickly but struggles with retention across stages... previously stored fast-weight knowledge is flushed and replaced by newer domains" — motivates retention mechanism for long-term CL.
- **Relevance:** Directly validates RecaMem's design split (frozen semantic backbone + plastic episodic memory) and flags the exact retention problem RecaMem's gated SLOW tier + consolidate-then-forget addresses.
- **Confidence:** Medium-High.

### 7b. Titans / MIRAS neural memory (context: F1)
- Covered in F1 (Titans, MIRAS, TTT). Short version: surprise-gated neural memory with decay; memory-only updates plateau (Titans Revisited) — need coordinated backbone adaptation or fast-weight inner loop. Operates at 100M+; direct <10M evidence sparse.
- **Relevance to F3:** Titans' surprise metric and decay gate are the large-model version of Sillage's surprise gating and RecaMem's write schedule.

## 8. Weight updates vs memory: comparison

| Dimension | Weight updates (FT/LoRA/TTT) | Non-parametric memory (RAG/episodic) | Plastic memory (RecaMem/Sillage) |
|---|---|---|---|
| **Catastrophic forgetting** | High risk (dense updates); sparse memory-FT reduces to ~11% drop | None (backbone frozen) | None (backbone frozen); bounded plastic state |
| **New knowledge fidelity** | High (weights encode it) | High for verbatim facts; weak for reasoning | Medium-high for associations; verbatim via episodic channel |
| **Compute at learn time** | Gradient steps (costly, GPU) | Embed + store (cheap, CPU) | No-grad writes (cheapest, CPU) |
| **Storage growth** | None (fixed params) | Grows with data (unless compressed) | Fixed (bounded matrix/state) |
| **Reasoning improvement** | Yes (weights change behavior) | No (only retrieval) | Partial (fast weights nudge readout) |
| **Small-model (<10M) fit** | ReLoRA fails at 11M; LoRA works 82M+ on CPU | Excellent (Dynamic Cheatsheet +20% on 1.7B) | Excellent (Sillage −38% ppl at 124M, 4.2 MB) |
| **CPU feasibility** | LoRA 82M–135M in 5–60 min; TTT needs ≥0.6B | Trivial | Trivial (numpy/torch CPU) |
| **Interpretability / audit** | Low (weights opaque) | High (stored facts + provenance) | Medium (stored state + write log) |
| **Reversibility / forgetting** | Hard (unlearning costly) | Easy (delete rows) | Designed-in (utility retirement, consolidate-then-forget) |
| **Stability-plasticity** | Tension (EWC/MAS mitigate) | Plasticity via storage; stability via frozen backbone | Two-tier (FAST plastic + SLOW gated) explicitly balances |

**Key findings from literature:**
- Memory is not always the bottleneck: "Memory Is Not the Bottleneck" (arXiv:2502.07274) shows with abundant exemplar memory, stability improves but *plasticity* drops; naive replay matches SOTA at 1/3–1/4 cost. Weight-space consolidation (rank-based resets + averaging) fixes plasticity cheaply.
- Non-parametric CL is viable and cheaper: HippoRAG 2 paves "non-parametric continual learning for LLMs"; Memento beats training-based methods with episodic memory.
- Small models suffer most from dense FT: "Continual Learning in LLMs" (arXiv:2402.17400) — smaller models show highest rates of both learning and forgetting; Phi-3.5-mini balances best under 10B.
- Sparse > dense: sparse memory finetuning 11% forgetting vs 89% (full FT) / 71% (LoRA) at equal new-knowledge acquisition.
- Memory-only updates plateau: Titans Revisited — "memory updates alone are insufficient for meaningful test-time learning... Without joint adaptation, the integration of new information is limited." (Motivates RecaMem's two-tier: FAST for immediate association + SLOW gated replay, plus episodic channel for verbatim facts.)
- Plasticity loss in small nets: continual backprop / selective weight reinit (Nature 2024, collas 2025 SWR) — small networks benefit from weight-level reinit. RecaMem avoids backbone updates entirely, sidestepping this.

## 9. CPU feasibility summary (small models)

| Method | Min model size | CPU? | Storage | Learn-time cost |
|---|---|---|---|---|
| Sillage (Hebbian) | Any causal LM (tested 124M, 0.6B) | Yes (numpy) | 4.2–26.5 MB fixed | ~2–8 min/10k tokens |
| Dynamic Cheatsheet / ReasoningBank | Black-box (tested 1.7B) | Yes | Snippets (grows) | LLM calls |
| Larimar | 1.3B | Memory on CPU | Grows w/ context | Encode+write |
| RecaMem (this) | Any (anchor optional) | Yes (torch CPU) | Bounded plastic state + SQLite | No-grad writes + sleep replay |
| LoRA on CPU | 82M–135M proven | Yes | 4–10 MB adapter | 5–60 min |
| DKVB | Encoder-only SLMs | Yes | Discrete KV | Localized updates |
| Sparse memory FT | Memory-layer LMs | GPU (training) | 1–10M pool | 1000 steps |
| Titans/TTT | ≥0.6B (TTT-NTP) | Research | Fast-weight MLP | Per-chunk GD |
| MemoryLLM/M+ | 7–8B | GPU + CPU LTM | 1–1.34B memory pool | 4 weeks |

**Practical conclusion for RecaMem's CPU target (<10M–100M):** non-parametric + plastic (no-gradient) memory is the dominant viable family; weight-update methods only become practical at ≥80M params with LoRA and ≥600M with TTT. RecaMem's design (frozen anchor + plastic adapter + episodic store + gated slow replay) sits exactly in the viable region and matches the strongest CPU evidence (Sillage).

## 10. Synthesis for RecaMem

**What to adopt (high confidence):**
1. **Surprise-gated writes** (Sillage, EM-LLM, Titans): RecaMem's FAST tier already records step_count; add explicit surprise scaling to `fast_write` (currently `surprise_factor` param exists but is passed through; ensure it modulates the write). Biggest single gain source (Sillage: surprise gating quadruples uniform-write gain).
2. **Amplitude encoding** (Sillage): store square roots of accumulated mass in the plastic adapter instead of counts — Sillage's largest single factor (+0.28 nats, P=1.000 every seed). Investigate whether `DeltaPlasticAdapter.update_associative_memory` can adopt amplitude scaling.
3. **Capacity sizing law** (Sillage): saturates at 0.5 writes/param; leaky decay recovers 2.3x. RecaMem's forgetting module should expose a leaky-decay knob and a capacity dial; document the 0.5-writes/param threshold.
4. **Recurrence-gated consolidation** (RecMem): consolidate episodic → semantic only when a topic recurs (threshold), reducing LLM/token cost. RecaMem's sleep replay could gate on recurrence.
5. **Event segmentation** (EM-LLM): Bayesian surprise boundaries for long streams; would let RecaMem segment continuous streams into episodes instead of fixed chunks.
6. **Success/failure episodic split** (Memory-R+): for agent tasks, store successful and failed traces separately; improves exploration.
7. **Two-tier is validated**: FwPKM's finding that fast (episodic) and slow (semantic) weights must be separated, and that fast weights flush across stages without retention, confirms RecaMem's gated SLOW tier + consolidate-then-forget design. Keep the gate.

**What to avoid:**
- Dense weight updates on the backbone at <100M (ReLoRA failure at 11M; LoRA only proven ≥82M on CPU).
- Unbounded memory stores without compression (MBC shows 0.3% suffices; Sillage shows fixed beats unbounded at 13x less memory on repetitive text but loses on long narrative — document the regime boundary).
- Memory-only updates without any adaptation path (Titans Revisited plateau) — keep SLOW tier + episodic channel.
- Mock anchor fallback (project rule; never re-add).

**Open questions for RecaMem:**
- Does the plastic adapter's write geometry allow amplitude (sqrt) encoding without breaking the fusion scorer's calibration?
- What is RecaMem's measured writes/param saturation threshold vs Sillage's 0.5?
- Can RecaMem's episodic store adopt a KG/PPR layer (HippoRAG 2) for associative recall without regressing factual recall?
- Should RecaMem add a fixed-size Hebbian tier (Sillage-style) alongside the plastic adapter, or merge concepts?
