# Design

First measure the existing C4 and C7 reference implementations in a single-process CPU harness with deterministic random inputs, configurable dimensions, seeds, warmup, thread count and sequence length. Collect forward and backward training time, incremental stateful step time, actual parameter counts, torch profiler operation breakdown, process RSS before/after (not claimed as peak), model/state sizes, hardware and versions. Validate whole-sequence versus streaming output and final state and report errors; do not treat throughput as quality evidence. Identical model shapes are a diagnostic comparison, not a parameter-matched quality comparison. Tests use small configurations and do not assert specific timings.

Candidate matrix and current decision: retain existing SQLite FTS5, exact dense and optional HNSW as reference; investigate Tantivy or USearch only against recall and lifecycle parity. Evaluate local Crawl4AI only after browser egress and sandbox gates in `autonomous-web-research`; parsers such as rs-trafilatura do not fetch or secure pages. Consider LangGraph for resumable orchestration only if it materially simplifies the existing coordinator; graph checkpoints do not replace canonical memory or permissions. For CPU models, compare local PyTorch/Transformers with optional ONNX Runtime/Optimum and potentially Rust Candle with pinned supported architecture and safetensors; do not assume Muir or existing checkpoints are supported and do not require GGUF. Quantization and speed depend on CPU and model.

A Rust path is optional, introduced only for a hotspot demonstrated by profiling. Compare a release-built PyO3/maturin extension to the reference including call/copy overhead, build provenance and CPU compatibility; compare forward, final state, backward gradients, numerical edge cases and streaming parity if it handles training. A forward-only implementation must never be used silently for training. Compare p50/p95, throughput, RSS/peak memory, setup cost and held-out quality; define thresholds before promotion. Never require Rust to install the default package; no unsafe download or silent fallback.

Security/license/dependency review and model/data acquisition must be recorded at implementation time. Test with representative 16 GB hardware before drawing hardware-specific conclusions. See `docs/cpu-library-research.md` for sources and limitations.
