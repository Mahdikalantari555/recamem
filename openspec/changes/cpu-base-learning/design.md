# Design

Use existing CPU PyTorch training (`scripts/train_lm.py`) and the existing `recamem-language-learning` work as the foundation, not a parallel trainer. Start with C4 and add opt-in Muir when `cpu-muir-core` satisfies its contracts. No GGUF, llama.cpp, network service or GPU is needed for the actual local training and generation path. Native checkpoint loading must validate architecture and tokenizer metadata; no silent random-model fallback.

Provide a small self-authored, redistributable corpus fixture and fixed, disjoint evaluation examples for offline functional tests. A fixture is not a base-knowledge dataset and must never support a language-understanding claim. For a substantive small-data experiment, reuse TinyStories preparation if a pinned, accessible source and redistribution/use terms can be verified; record exact source URL, version or revision, license, download instructions, hashes, split/deduplication policy and token counts. If source or rights are unavailable, mark the run blocked and do not invent a dataset or license. Do not commit large downloads or checkpoints. Provide a deterministic capped subset and split by document before tokenizer fitting, with near-duplicate checks across splits; keep the final evaluation split untouched by tuning and incremental lessons.

Run a CPU smoke test first, followed by an explicitly budgeted experiment: configuration, threads, RAM, tokens, sequence length, seed, wall time, checkpoint/resume and storage all recorded. Estimate expected duration on the user's own hardware from a short measured pilot, not generic promises. Compare validation bits per byte and n-gram baselines, sampled generations, and held-out compositional/novel examples; report uncertainty and leakage checks. TinyStories predominantly teaches a constrained story domain, not broad factual knowledge. Emerging behavior must be measured across scales or training checkpoints and compared with baselines, not asserted from a few examples.

After base training, incremental fact teaching uses the existing RecaMem ingest and retrieval lifecycle with provenance, correction/supersession, persistent state and explicit memory injection into a native model generation path. Specify an integration adapter if existing generator contracts do not accept CandidateLM; don't claim it exists until tested. Measure before/after, no-memory and shuffled-memory controls, old facts and corrections across restarts. Never claim the base weights learned a fact merely because retrieval supplied it. Optional later continued training uses replay, a held-out retention gate and atomic checkpoint rollback; document forgetting and failure. No implicit weight updates from unverified conversations.
